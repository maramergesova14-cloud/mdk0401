# Реестр рисков и план тестирования

## 1. Реестр рисков

| № | Риск | Вероятность | Влияние | Предупреждение и реакция |
|---|---|---|---|---|
| 1 | Некорректные исходные данные | Средняя | Высокое | Проверять обязательные поля и выборку записей; ошибочные данные исправлять до импорта |
| 2 | Потеря данных | Низкая/средняя | Высокое | Создавать резервные копии и периодически проверять восстановление |
| 3 | Ошибки в связях оценок и посещаемости | Средняя | Высокое | Проверять выбранного студента, предмет и дату в каждом тестовом сценарии |
| 4 | Пользователи не знакомы с системой | Средняя | Среднее | Провести обучение и подготовить краткую инструкцию |
| 5 | Недоступность приложения | Средняя | Высокое | Проверить запуск, подключение к БД и журнал ошибок; назначить ответственного |
| 6 | Нереализованная функция принята за готовую | Средняя | Высокое | Сверять требования с фактическими возможностями; не включать непроверенные функции в акт приёмки |
| 7 | Раскрытие персональных данных | Низкая/средняя | Высокое | Использовать тестовые данные, ограничивать доступ к среде и не публиковать секреты в репозитории |

Оценки вероятности предварительные и должны уточняться с командой проекта.

## 2. Подход к тестированию

Проверки выполняются в тестовой среде на учебных данных. Для каждой проверки фиксируются дата, версия приложения, входные данные, ожидаемый результат, фактический результат и статус.

## 3. Базовые тестовые сценарии

| ID | Действие | Ожидаемый результат |
|---|---|---|
| T01 | Получить список студентов через API | Возвращается список в ожидаемом формате |
| T02 | Создать студента с корректными данными | Запись сохраняется и появляется в списке |
| T03 | Изменить данные студента | Новые значения сохраняются |
| T04 | Удалить тестовую запись студента | Запись удаляется либо операция корректно отклоняется при связанных данных |
| T05 | Получить список предметов | Возвращаются существующие предметы |
| T06 | Создать оценку с существующими студентом и предметом | Оценка сохраняется с корректными связями |
| T07 | Получить оценку и проверить дату, значение и комментарий | Данные совпадают с введёнными |
| T08 | Создать запись посещаемости | Студент, предмет, дата и статус отображаются правильно |
| T09 | Передать некорректные или неполные данные | API сообщает об ошибке валидации, если поле обязательно |
| T10 | Открыть административную панель | Уполномоченный администратор может войти и видеть настроенные модели |
| T11 | Перезапустить приложение и повторить чтение | Сохранённые данные остаются доступными |
| T12 | Проверить резервную копию | Данные можно восстановить в тестовой среде согласно принятой процедуре |

Результаты должны заполняться по фактическому запуску тестов. Таблица выше — перечень запланированных проверок, а не заявление, что все они успешно пройдены.

## 4. Проверка готовности к запуску

Запуск допускается, если:
- критические сценарии прошли проверку;
- нет открытых критических дефектов;
- подтверждены резервное копирование и восстановление;
- инструкции подготовлены;
- ограничения системы доведены до пользователей;
- назначен ответственный за поддержку.

## 5. Форма записи дефекта

Для найденной ошибки записываются:
- идентификатор;
- дата обнаружения;
- шаги воспроизведения;
- ожидаемый и фактический результат;
- серьёзность;
- ответственный;
- статус исправления;
- результат повторной проверки.
