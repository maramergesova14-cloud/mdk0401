# МДК.04.01 — План внедрения программного обеспечения

## Проект: «Электронный журнал группы»

**Тип работы:** план внедрения информационной системы  
**Объект внедрения:** веб-система для ведения успеваемости и посещаемости студентов.  
**Плановая продолжительность:** 15 рабочих дней.  
**Основной результат:** подготовленная, проверенная и переданная пользователям система электронного журнала.

## 1. Цель и задачи внедрения

Цель проекта — организовать единый электронный учёт оценок и посещаемости, сократить ручную работу преподавателей и упростить подготовку учебной отчётности.

Задачи:
- уточнить требования преподавателей и администрации;
- подготовить серверную и пользовательскую среду;
- проверить структуру данных и справочники;
- настроить и проверить функции учёта студентов, предметов, оценок и посещаемости;
- подготовить инструкции и провести обучение;
- выполнить пробный запуск и организовать поддержку.

## 2. Границы проекта

В рамках внедрения рассматриваются:
- справочник студентов и учебных предметов;
- записи об оценках;
- учёт посещаемости;
- просмотр и проверка данных через API и административную панель;
- подготовка пользователей к работе с системой.

Разграничение доступа по ролям, полноценная авторизация, автоматический расчёт среднего балла и расширенные отчёты относятся к проектным требованиям и должны быть отдельно реализованы и проверены, прежде чем считать их готовыми функциями. Наличие описания в проекте само по себе не означает, что функция уже работает.

## 3. Этапы и календарный план

| № | Этап | Срок | Основной результат |
|---|---|---:|---|
| 1 | Анализ требований | 2 дня | Согласованный перечень требований |
| 2 | Подготовка среды | 2 дня | Подготовленная среда и резервная копия исходных данных |
| 3 | Настройка системы | 5 дней | Настроенные справочники и основные сценарии |
| 4 | Тестирование | 2 дня | Протокол проверок и список исправлений |
| 5 | Обучение пользователей | 2 дня | Инструкции и обученные пользователи |
| 6 | Запуск и первичное сопровождение | 2 дня | Решение о запуске и журнал замечаний |
| **Итого** |  | **15 рабочих дней** |  |

Подробный план по этапам, ответственным и контрольным точкам приведён в файле [PLAN_VNEDRENIYA.md](PLAN_VNEDRENIYA.md).

## 4. Участники проекта

- **Руководитель проекта:** согласует требования, сроки и результаты этапов.
- **Системный администратор:** подготавливает среду, резервное копирование и доступность системы.
- **Разработчик/специалист настройки:** настраивает приложение и исправляет ошибки.
- **Представитель учебной части:** проверяет справочники и корректность учебных данных.
- **Тестировщик:** выполняет проверки по тестовым сценариям.
- **Преподаватели и сотрудники:** участвуют в обучении и пробной эксплуатации.

В учебном проекте эти роли могут выполнять несколько человек.

## 5. Основные риски

| Риск | Меры снижения |
|---|---|
| Ошибки при переносе данных | Проверять записи по контрольной выборке и сохранять исходную копию |
| Недостаточная подготовка пользователей | Провести инструктаж и выдать краткую инструкцию |
| Обнаружение ошибок при проверке | Фиксировать дефект, ответственного и результат повторного теста |
| Потеря данных | Настроить регулярные резервные копии и проверить восстановление |
| Недоступность сервера или сети | Проверить инфраструктуру до запуска и определить ответственного за поддержку |
| Ожидание функций, которые ещё не реализованы | Сверить фактические возможности с перечнем требований до приёмки |

Подробная таблица рисков и тестовые сценарии находятся в [RISKI_I_TESTIROVANIE.md](RISKI_I_TESTIROVANIE.md).

## 6. Критерии успешного внедрения

Внедрение можно считать завершённым, если:
1. система запускается в подготовленной среде;
2. основные операции со студентами, предметами, оценками и посещаемостью проходят проверки;
3. данные после создания и изменения сохраняются корректно;
4. нет открытых критических ошибок;
5. назначенные пользователи получили инструкции;
6. определены порядок резервного копирования и контакт ответственного за поддержку;
7. заказчик/преподаватель подтвердил результаты приёмки.

Критерии оцениваются по результатам проверок, а не только по факту запуска приложения.
