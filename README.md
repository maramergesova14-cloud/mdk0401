# МДК.04.01 — Внедрение программы
## Тема: Электронный журнал группы

### Главная цель
Внедрить электронный журнал группы для централизованного учёта студентов, учебных предметов, оценок и посещаемости. Система должна упростить работу с учебными данными, сократить количество ошибок при заполнении бумажных записей и обеспечить быстрый доступ к информации.

### Ожидаемые результаты проекта (KPI)
1. **Единое хранение данных:** сведения о студентах, предметах, оценках и посещаемости находятся в одной системе.
2. **Сокращение ручной работы:** добавление и поиск учебных записей выполняются через приложение и API.
3. **Актуальность информации:** изменения сохраняются в базе данных и доступны при повторном обращении.
4. **Контроль доступа:** доступ к функциям управления данными предоставляется после авторизации.
5. **Надёжность хранения:** предусмотрена работа с PostgreSQL; SQLite может использоваться как локальный вариант.

### Содержание плана внедрения

| Этап | Работы | Результат этапа |
|---|---|---|
| 1. Анализ и проектирование | Определить пользователей, состав данных и функции журнала | Описание требований и структуры данных |
| 2. Подготовка среды | Установить Python, Django, зависимости и настроить базу данных | Подготовленная среда для запуска |
| 3. Настройка и наполнение | Настроить приложения для студентов, предметов, оценок и посещаемости | Основные разделы электронного журнала готовы к работе |
| 4. Проверка | Проверить авторизацию, API, создание и изменение записей | Список результатов проверок и исправленных ошибок |
| 5. Ввод в эксплуатацию | Подготовить инструкцию, создать администратора и запустить приложение | Рабочая версия электронного журнала |

### Ответственные
1. **Руководитель проекта** — планирование работ и контроль сроков.
2. **Разработчик** — настройка Django, API и логики приложения.
3. **Администратор базы данных** — настройка PostgreSQL, создание базы и резервное копирование.
4. **Тестировщик / пользователь** — проверка сценариев работы и фиксация замечаний.
5. **Преподаватель или куратор группы** — оценка удобства и соответствия учебным задачам.

### Необходимые ресурсы
1. **Человеческие:** разработчик, тестировщик, представитель пользователей.
2. **Технические:** компьютер, доступ к интернету.
3. **Программные:** Python, Django, Django REST Framework, PostgreSQL или SQLite, Git и GitHub.
4. **Информационные:** список студентов, перечень предметов и правила учёта оценок и посещаемости.
5. **Временные:** время на разработку, проверку и подготовку инструкции.

### Критерии успешного завершения
1. Приложение запускается по инструкции без критических ошибок.
2. Можно просматривать и добавлять сведения о студентах и предметах.
3. Оценки и посещаемость связываются с нужными студентами и предметами.
4. Данные сохраняются в выбранной базе и доступны после перезапуска приложения.
5. Авторизация и административный доступ работают корректно.
6. Подготовлена инструкция по установке и запуску проекта.

### Основные модули электронного журнала

#### Модуль учётных записей и авторизации
Обеспечивает вход пользователей и получение токенов доступа. В проекте используется JWT-авторизация.

#### Модуль студентов
Хранит сведения о студентах и предоставляет операции просмотра, добавления, изменения и удаления записей в пределах настроенных прав доступа.

#### Модуль учебных предметов
Содержит справочник дисциплин, используемый при ведении журнала.

#### Модуль оценок
Позволяет вести записи об оценках студентов по учебным предметам.

#### Модуль посещаемости
Предназначен для фиксации посещения занятий студентами.

#### Модуль отчётности
Предоставляет сводную и индивидуальную информацию по учебным данным в соответствии с реализованными API-функциями.

### Результат внедрения
Результатом проекта должна стать доступная для запуска система электронного журнала, в которой учебные данные хранятся централизованно, а основные операции выполняются через веб-приложение, административную панель и API.
